# Supabase

Two long-lived projects back the two environments (see `docs/devops-strategy.md` §5):

| Environment | Project (suggested name) | Branch  |
| ----------- | ------------------------ | ------- |
| Testing     | `tcg-tracker-testing`    | develop |
| Production  | `tcg-tracker-prod`       | main    |

## Layout

- `migrations/` — versioned, **forward-only** SQL. Never edit a merged file; add a new one.
- `seed.sql` — deterministic sample data for **Testing only**. Real cards only.
- `config.toml` — generated by `supabase init` (not yet run; needs the CLI).

## First-time local setup (deferred — needs the Supabase CLI + your account)

```bash
# Install the CLI (Homebrew) or use npx
brew install supabase/tap/supabase

# Generate config.toml in this folder
supabase init

# Link to an environment's project, then apply migrations
supabase link --project-ref <project-ref>
supabase db push
```

CI applies pending migrations automatically on merge to `develop` (Testing) and
`main` (Production) via `.github/workflows/deploy.yml`, before the deploy is trusted.

**Before the first real CSV import into Production**, enable automated backups / PITR
on the prod project — that durability guarantee is the reason this stack was chosen.
